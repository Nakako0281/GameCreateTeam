# 人間向け 操作マニュアル (`docs/HUMAN_OPERATIONS_GUIDE.md`)

このドキュメントは、**AutoGrowth Studio（TemotoBox）** において人間（**①法的最終責任者・②外部実務担当・③対等なチームメンバー** の 3 ロール）が「どこで・どんな指示を出せるか」「使えるコマンド・フレーズは何か」「AIの成果物や異常停止をどう扱うか」を迷わず参照するための実践ガイドです。

---

## 1. この組織での役割分担（3ロール分離）

人間の意見は通常議論では「鶴の一声」にせず対等な1票として扱い（ロール3）、法的・対外責任とマージ操作のみ人間が担うことで、自律性と安全性を両立させています（詳細: [ADR-005](ADR/ADR-005-governance-escalation-and-roles.md)）。

- **人間にお願いすること（ロール1：法的最終責任者 ／ ロール2：外部実務担当）**:
  1. **PR（Pull Request）の最終確認・マージ**（AIは自己マージ・`main`/`dev` 直Pushをハーネスで物理禁止されています）
  2. **外部認証・契約・費用作業**（独自ドメイン購入、Cloudflare / GA4 / GSC / AdSense 管理画面操作）
  3. **集客記事の公開投稿**（AIが作成した Zenn / Qiita / X 記事ドラフトの投稿）
  4. **チームメンバー（ロール3）としての意見・疑問・要望起票**: 気づいた違和感や改善アイデアを Issue やチャットで投げる（対等な論拠で協議し、最終責任者権限を行使する場合のみ明示します）。
- **AIトップリーダー（業務執行責任）に任せてよいこと**:
  - 市場調査、SEO/LLMO設計、UI/UX設計、実装、単体テスト・E2E実機漏洩ゼロ証明、セキュリティ/ライセンス監査、リモートCI通過確認、ハーネス・機械チェック進化。

## 2. どこで・どう指示できるか（3つの入口）

### 入口①：GitHub Issue（普段の要望・不具合・完了報告のメイン窓口）
普段気づいたことや作業完了連絡は、チャットではなく **GitHub Issues** に書くと管理が一番ラクになります。

| ケース | やり方 |
| :--- | :--- |
| **要望・不具合・改善アイデアを出したい** | GitHub の **New issue** からラベル無しのまま自由に書いてOKです（リポジトリ所有者が起票したメモは `trusted_issues` / `unlabeled_trusted_issues` としてAIが最優先検知し、自動でラベル整理と実装へ進めます）。<br>・「何が気になったか / どうなると嬉しいか」だけ書けば十分です（実装方法はAIが最善案を決めます）。 |
| **AIからの依頼（`owner:human` Issue）を完了した** | 該当の `[Human]` Issue に結果（URLや設定値など）をコメントして **Close** するだけでOKです。次回のAI起動時に `npm run ops:status` が自動検知して後続作業へ進みます。 |

---

### 入口②：チャットでの直接指示（今すぐ動かしたい・議論したいとき）
新しいチャットを開いても `AGENTS.md` と `.agents/rules/AGENTS.md` が自動読み込みされるため、長い説明は不要です。以下の**一言フレーズ**をそのまま打つと、組織ルール（記憶復元 ➔ 実装 ➔ 全機械チェック ➔ Draft PR ➔ リモートCI通過確認 ➔ 記録更新）に乗ったサイクルが起動します。

| やりたいこと | チャットで打つ一言（そのままコピペ可） | 起動するスキル・挙動 |
| :--- | :--- | :--- |
| **優先タスクを適量まとめて進めてほしい** | **`daily-ops` で進めて** | [daily-ops](../.agents/skills/daily-ops/SKILL.md)：人間完了Issueや未対応Issueを確認し、タスク規模（S/M/L）と関連性を見極めて適量をバッチ統合・自律消化（軽量タスクは1PRへ集約）〜リモートCI通過PR作成まで実行 |
| **新ツールを企画・追加してほしい** | **`new-tool` で〇〇のツールを作って**<br>（または「ロードマップの次のツールを `new-tool` で作って」） | [new-tool](../.agents/skills/new-tool/SKILL.md)：需要調査・辛口監査・純粋TSロジック・UI・1,500字解説/FAQ・E2Eゼロ送信証明〜リモートCI通過PR作成 |
| **振り返り・再発防止の仕組み強化をしてほしい** | **`audit-and-evolve` で振り返りと仕組み強化をして** | [audit-and-evolve](../.agents/skills/audit-and-evolve/SKILL.md)：直近のPR/Issue/KPI/失敗を総括し、`POSTMORTEM` 更新＋**新しい機械チェックを実装** |
| **特定の指摘を組織成長ごと直してほしい** | **「〇〇が気になる。組織ルール通りに原因分析・再発防止の機械チェック追加まで含めて対応して」** | つぎはぎ修正をせず、`POSTMORTEM` 記録 ➔ 自動テスト/監査追加 ➔ 修正実装 ➔ リモートCI通過PR作成 |

> **運用のコツ**: 同じチャットを長く続けるより、タスク区切りで**新しいチャットを開いて一言指示を出す**方が精度が安定し、永続ドキュメント（`docs/STATE.md` 等）による記憶引き継ぎも毎回検証できます。

---

### 入口③：定期自動化（放置で回る定例サイクル）
Antigravity の定期自動化および GitHub Actions により、以下のサイクルが自動で回ります。

| 自動化名 | スケジュール | 内容 |
| :--- | :--- | :--- |
| **Daily AutoGrowth Studio Ops** | 毎日 9:00 (JST) | Issue・PR確認 ➔ 規模（S/M/L）に応じた適量バッチ消化 ➔ 検証＆リモートCI全通過PR作成 |
| **Weekly AutoGrowth Studio Retrospective** | 毎週月曜 10:00 (JST) | 週次振り返り ➔ KPI・失敗整理 ➔ 再発防止の機械チェック強化PR作成 |
| **GitHub Actions Weekly Audit** | 毎週月曜 9:00 (JST) | GitHub サーバー側で `npm audit`・ビルド・各種監査を自動実行し、異常時にAI Issueを自動起票 |

> **注意**: Antigravity のローカル定期自動化（上2つ）は **Automations ダッシュボードで有効化（Enabled）** されており、かつ **実行時刻に PC（Antigravity）が起動している場合** に動作します。

## 3. 併用できるスラッシュコマンド一覧（チャット入力欄）

| コマンド | 使いどころ |
| :--- | :--- |
| **`/learn`** | AIのミスや指摘から、ルール（`GEMINI.md` / `AGENTS.md`）やスキル自体を恒久改善したいとき（提案確認後に反映） |

| **`/plan`** | 複雑な変更をいきなりコード修正せず、先に詳細な計画を作って確認したいとき |

| **`/teamwork`** | 複数エージェントで並列に大きな開発・調査を進めたいとき |
| **`/boost`** | 深い調査・多角的な設計検討・厳格な検証を要する高難度タスクのとき |

## 4. よく使うローカルコマンド一覧（ターミナル用チートシート）

```bash
# ローカル開発サーバー起動（http://localhost:4321）
npm run dev

# 本番静的ビルド＆プレビュー起動
npm run build && npm run preview

# ローカル全8機械ゲートを一括実行（CI環境一致・型・単体テスト・ビルド・セキュリティ・SEO・メモリ・E2E）
npm run check:all

# GitHub上のオープンIssue・人間完了Issue・オープンPRを一括確認
npm run ops:status

# 指定PRのリモートGitHub Actions CI完了を待機・検証（全緑ならDraft→Readyへ昇格）
npm run ops:ready-pr -- <PR番号>
```

## 5. ブランチ運用・PRレビュー・リリースフローの見方

本リポジトリは **`main`（本番）と `dev`（テスト統合）の2層ブランチ運用** を採用しています。

```text
作業ブランチ (feat/*, docs/*) ──PR──▶ dev (常設テスト環境) ──リリースPR──▶ main (本番)
```

1. **Draft PR で作成**: AI が `dev` から作業ブランチを切り、`create-pr` を実行すると必ず **`dev` 宛ての Draft（下書き）PR** として作成されます。Draft の間は作業中または CI 実行中なのでレビュー不要です。
   - ※ `docs/**`・`.agents/**`・`README.md`・`AGENTS.md` のみのドキュメントPRは、GitHub Actions で軽量チェックのみ実行して高速に完了します。
2. **リモート CI 全通過 ➔ 自動 Ready 昇格**: AI が `npm run ops:ready-pr -- <PR番号>` を実行し、リモートチェックが全件 `success` になったときだけ **Ready for Review** へ昇格して人間へ確認依頼が届きます（失敗時は昇格が物理的に拒否されます）。
3. **人間による `dev` マージ（テスト反映）**: Ready になった PR を確認してマージすると、Cloudflare の `dev` テスト環境（`*.workers.dev`・検索非公開）へ自動反映されます。
4. **本番リリース（`dev` ➔ `main`）**: テスト環境でまとまった成果を確認できたら、`dev` ➔ `main` のリリース PR をマージして本番公開します。
5. **異常系・3層ハーネスによる自動停止（`main` 先行乖離・保護ファイル編集時）**:
   - 緊急修正等で `main` が `dev` より先行し差分が生じた場合、`.agents/hooks.json`・`ops_github.mjs`・`ci.yml` の3層ハーネスが変則的な `main` 宛てPRや連鎖PRを自動検知して停止します。その際AIは4点セット（事実・選択肢・推奨案・確認点）を提示して事前相談するため、まず `main ➔ dev` 同期で正常系へ戻してからリリースへ進みます。
   - また憲法（`AGENTS.md`）・ハーネス（`.agents/hooks.json`）・CI・法務境界ファイル等の変更時や `main` 操作時は、`force_ask` により毎回ユーザー確認プロンプトが表示されます。
