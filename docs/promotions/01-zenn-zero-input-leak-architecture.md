## はじめに：なぜ「ブラウザ完結・入力データ送信ゼロ」のワークベンチを作ったのか

業務で「CSVの文字化けを直したい」「写真からGPS位置情報（EXIF）を消したい」「生成AIに投げる前にメールや設定ファイルから個人情報・APIキーを伏せたい」と思ったとき、検索上位に出てくる無料Webツールの多くは**入力ファイルやテキストを一度サーバーへアップロードする仕組み**になっています。あるいは同じサイト内で「一部はブラウザ処理、別の一部はサーバー処理」が混在し、ソースコードも非公開で「運営を信じるしかない」状態になりがちです。

多くの企業では社外秘データを外部変換サーバーへ送ること自体がセキュリティ規定違反になりますし、かといって便利なChrome拡張機能は「閲覧中の全ページの入力欄を読み取れる権限」を要求するケースが少なくありません。

そこで今回、**生成AIや社外共有の前に、機密データやファイルを外部サーバーへ一切送信せずブラウザ単一タブ内のメモリとCanvasだけで安全に下ごしらえでき、しかもソース公開と自動テストで第三者からも検証可能な無料実務ワークベンチ「TemotoBox（てもとボックス）」**を開発しました。

- **公開サイト**: https://temotobox.com/
- **ソースコード（透明性検証用）**: https://github.com/Nakako0281/GameCreateTeam

本記事では、単なる「送っていません（口約束）」ではなく、**ビルド前後の静的監査と2層のPlaywright E2Eテストによって「入力データの外部送信ゼロ」を毎回CIで機械証明している技術設計**を解説します。

---

## 1. アーキテクチャ全体像：サーバーAPIを持たない静的SSG ＋ React Islands

TemotoBox は以下の技術スタックで構成されており、バックエンドAPIサーバーもデータベースも一切持っていません（サーバー処理型ツールの混在ゼロ）。

- **フレームワーク**: Astro（`output: 'static'` 完全静的生成）＋ React 18 Islands
- **言語・UI**: TypeScript（strict）＋ Tailwind CSS v4
- **ホスティング**: Cloudflare Pages（静的配信 ＋ `_headers` によるセキュリティヘッダー）

```text
[ユーザーのブラウザ（単一タブ）]
  ├── HTML / ガイド解説 / FAQ / JSON-LD ── Astro SSG が静的HTMLとして配信
  └── ツール実処理（PIIマスク / CSV変換 / Canvas EXIF削除 / Markdown整形 / 設定ファイル秘匿化）
        └── 純粋 TypeScript + HTML5 Canvas + Web File API（メモリ内で完結・サーバー送信なし）
```

ツール本体だけを React Island（`client:load`）として動かし、解説文やFAQは純粋な静的HTMLで配信しているため、**初期表示の高速さ**と**入力データの完全ローカル処理**を両立しています。

---

## 2. 技術ポイント①：HTML5 Canvas 再描画による「物理的なEXIF/GPS完全削除」

[画像 EXIF/GPS位置情報 完全削除＆WebP/JPG一括軽量化](https://temotobox.com/tools/image-exif-cleaner/) では、あえてバイナリチャンク（APP1等）を文字列置換的に切り貼りするのではなく、**二段階のバイナリ検証＋Canvas再描画**を採用しています。

1. **削除前のバイナリ診断**: 読み込んだJPEG/PNGの先頭ヘッダー・セグメントを純粋TypeScriptで走査し、`Exif` や GPS IFDポインタ（`0x8825`）、XMP・IPTC・PNGテキストチャンク（`tEXt` / `iTXt`）の有無を可視化します。
2. **HTML5 Canvas へのピクセル再描画**: 画像を一度デコードし、ピクセル情報だけを Canvas へ描き直したうえで `canvas.toBlob()` で新しい画像（WebP / JPEG / PNG）を生成します。メタデータ領域は構造上引き継がれません。
3. **削除後の再検査**: 生成された出力バイナリにも同じバイナリ検査エンジンを再度走らせ、「検出 0 件」であることを実測確認してからダウンロードリンクを出します。

## 3. 技術ポイント②：AST的な構文保護と正規表現の境界設計（AI PIIマスカー ＆ 設定ファイル秘匿化）

自然言語や設定ファイルを扱うツールでは、「誤って壊す」「取りこぼす」の両方を防ぐ設計が重要になります。

- **[AI入力前・個人情報(PII)自動マスキング＆回答復元](https://temotobox.com/tools/ai-pii-masker/)**:
  - OpenAI/GitHub/AWSキー、JWT、メール、電話、Luhn検算を通過したカード番号、日本法人名、氏名＋敬称を優先度付きで検出し、`[ORG_1]` や `[PERSON_1]` のような一意なトークンへ置換します。
  - AIが出力した回答内の `[PERSON_1]` や Markdownエスケープ（`\[PERSON\_1\]`）をブラウザ内で元の文字列へ自動復元でき、元の辞書の対応表に一致しない未解決トークンが残った場合は警告を表示します。
- **[.env / JSON / YAML / ログ 秘匿値サニタイズ＆変換](https://temotobox.com/tools/config-sanitizer/)**:
  - 単純な正規表現置換では壊れがちな、値中に `#` を含む `.env` パスワード、マルチドキュメント（`---` 区切り）の Kubernetes YAML、`kind: Secret` の Base64 `data` 領域、ユーザー名・パスワード付き接続URIの末尾 `@` 境界などを構文解析したうえで安全に `<REDACTED>` や `.env.example` 形式へ整形します。

## 4. 「入力データを送っていない」を毎回CIで機械証明する3つのゲート

口頭の説明だけでは信頼性が担保できないため、TemotoBox のすべてのPRではローカルおよび GitHub Actions CI で以下の3つの機械監査を毎回通過させています。

### ① 静的セキュリティ監査 (`scripts/audit-security.mjs`)
`src/` 配下の全ソースコードから、許可されない外部通信API・危険構文の混入を自動検査し、1件でも見つかればビルドを落とします。

- 禁止API: `fetch()`、`XMLHttpRequest`、`navigator.sendBeacon`、`new WebSocket`、`new EventSource`、外部HTTP `<form action>`、`eval()`、`new Function()`、`dangerouslySetInnerHTML`
- さらに `public/_headers` の厳格な CSP・`X-Frame-Options: DENY`・`nosniff` の維持、および全直接依存パッケージのライセンス（GPL等の感染性ライセンス拒否）も同時に監査します。

### ② 誇大表現防止監査 (`scripts/audit-seo-adsense.mjs`)
アクセス解析（GA4）や広告配信（Google AdSense）を本番導入した際、それらに伴うGoogleドメインへの通信自体は発生します。にもかかわらずサイト上で無条件に「外部通信ゼロ」と書いてしまうと実態と矛盾します。

そこで `findUnqualifiedZeroSendClaims` を実装し、全公開HTMLと `README.md` に対して「入力データ」「ファイル内容」「ツール由来」といった限定語を伴わない無条件の「ゼロ送信 / 外部通信ゼロ / 1バイトも送らない」表現を機械的に検出・ブロックしています。

### ③ 2層の Playwright E2E 漏洩ゼロ証明 (`test:e2e` ＋ `test:e2e:ads`)
最も重要なのが、実際のブラウザ（Chromium）で公開中の全ツールを操作した際の検証です。TemotoBox では **2種類のビルドに対して E2E を実行** しています。

1. **解析・広告未設定ビルド (`npm run test:e2e`)**:
   全ページ描画および全6ツールのサンプル操作・入力変換中に、`127.0.0.1` / `localhost`（および `data:` / `blob:`）以外の外部リクエストが **0件** であることを証明します。
2. **解析・広告有効ビルド (`npm run test:e2e:ads`)**:
   ダミーの `PUBLIC_ADSENSE_CLIENT` / `PUBLIC_GA_ID` を埋め込んで本番構成と同等にビルドし、外部通信を `page.route` でインターセプト・遮断した状態で全6ツールへ**固有のカナリア文字列（架空のメールアドレス・APIキー・社名・設定キー等）**を入力して操作します。そのうえで以下を自動検証します。
   - AdSense / GA4 スクリプトへのリクエスト試行が実際に捕捉されたこと（有効ビルドの実測）
   - 許可された広告・解析ホスト以外（例：Markdownに埋め込んだダミーの外部画像トラッカーURL等）への通信試行が0件であること
   - 捕捉された **すべてのリクエストの URL・デコードURL・ヘッダ・POST本文** および **`window.dataLayer` 内部** に、カナリア文字列（生文字列・URLエンコード・Base64表現含む）が1文字も含まれていないこと

## 5. ご自身のブラウザ（DevTools）で今すぐ検証する方法

利用者ご自身でも、10秒で入力データの非送信を確認できます。

1. 任意のツール（例：`https://temotobox.com/tools/ai-pii-masker/`）を開き、`F12`（Macは `Cmd + Option + I`）で開発者ツールの **Network** タブを開きます。
2. 消去アイコンで初期表示時のログをクリアします。
3. テキスト貼り付け・サンプル実行・CSV変換・EXIF削除を実行しても、**ツール操作に伴うAPI送信（POST等）が一切発生しないこと**を確認できます（ページ表示後に一時的にネットワークをオフラインにしてもそのまま動作します）。

## おわりに

実務で使える無料Webツールを作るうえで、「個人情報をサーバーへ送らない・DBを持たない」という設計は、ユーザーにとっての安全性だけでなく、運用者にとってもサーバー維持費や情報漏洩リスクを抑えられる合理的な選択でした。
