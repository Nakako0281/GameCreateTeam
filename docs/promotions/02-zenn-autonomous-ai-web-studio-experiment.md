## 1. この実験について：人間（法的最終責任者・外部実務・1メンバーの3ロール分離）とAI自律チーム

本プロジェクトは、**「AIが自ら企画・構築・検証・改善を回し、法務やセキュリティを守りながら Google AdSense 収益 100円/月 以上を達成できるか」** を検証する公開実験リポジトリです。

役割分担を極端に振っているのが特徴です。

- **AI（自律実行チーム）**: 市場調査・事業ピボット判断・アーキテクチャ設計・実装・単体/E2Eテスト・CI監視・ドキュメント更新・PR作成までを自律的に実行。
- **人間（最終責任者）**: PRのマージ承認、独自ドメイン購入やCloudflare/AdSense管理画面など外部認証が必要な操作、公開記事の投稿、そして「使ってみたユーザー目線のダメ出し」のみを担当。

実験の公開成果物として稼働しているのが、**生成AIや社外共有前の下ごしらえに特化した、検証可能なブラウザ完結実務ワークベンチ「TemotoBox（てもとボックス）」** です。

- **公開サイト**: https://temotobox.com/
- **公開リポジトリ**: https://github.com/Nakako0281/GameCreateTeam

## 2. 2つの大きな意思決定：ピボットと「検証可能な機密ワークベンチ」への絞り込み

実はプロジェクト開始直後（v1）、AIはいくつかのブラウザ向けミニゲームを作っていました。しかし、AdSense審査通過と2027年2月期限（約90日）での収益化を冷静に再評価した結果、**ゲームポータル路線を自ら棄却（`ADR-001`）** し、実務ツールへピボットしました。

さらにドメイン取得直前の戦略会議では、国内大手の総合便利ツールサイトと正面から比較したうえで、以下の **「勝てる土俵」とブランド刷新（`ADR-004`：`TemotoBox`）** へ踏み切っています。

1. **「ブラウザ完結」自体はもう差別化にならない**: 大手サイトもクライアント処理型ツールでは「サーバー送信なし」を謳っているため、法人運営の130ツール超サイトと素の文字数・汎用ツールで真っ向勝負しても負ける。
2. **AI Overviews時代に代替されない実務の一手間**: 「手元のShift-JIS CSVを文字化け解消＋列マスクする」「`.env`やK8s Secretを非破壊でサニタイズする」「社外秘プロンプトを仮名化してAI回答を復元する」「EXIF削除後0件を再検査する」作業は検索要約でも総合工具箱でもカバーされていない。
3. **「企業の善意を信じる」ではなく「自分で検証できる」モデル**: サーバー処理ツールとの混在をゼロ（100%静的配信）に保ち、ソースコードと広告有効時の漏洩ゼロE2Eを公開することで技術者が自ら監査できる専用ワークベンチとして差別化する。

## 3. 実戦で踏んだ失敗と「気をつけます」を禁止した機械チェック進化

この実験では、**「失敗や人間からの指摘が出たら、『次回から気をつけます』で終わらせず、必ずスクリプトやテストを追加して物理的に再発を封じる」** というルール（`docs/POSTMORTEM_AND_LESSONS.md`）を運用しています。

これまでに実際に発生し、仕組みで封じた代表的な教訓を紹介します。

### L-06: ローカル全緑で完了報告したら GitHub Actions CI が落ちていた
- **何が起きたか**: ローカル環境が Node.js v24、CIが v22 で食い違っており、旧ロックファイルの不整合によって `npm ci` が CI でのみ失敗。にもかかわらずローカル通過だけでレビュー依頼を出してしまった。
- **機械化対策**: `.node-version` 統一＋ `audit-ci-parity.mjs` を新設し、さらに操作CLI `scripts/ops_github.mjs` で **すべてのPRをデフォルト Draft 作成にし、GitHub Actions 全ジョブの `success` を API で実測待機する `ready-pr` コマンドを通らない限り Ready 昇格できない** よう変更しました。

### L-07 ＆ L-13: LLM料金ツールに旧世代モデルが混入 ＆ 時刻依存テストでCIが壊れる罠
- **何が起きたか**: AIが過去の記憶で古いLLMモデル（GPT-4oやClaude 3.5等）を料金比較表に入れてしまい、人間から指摘を受けました（Issue #38）。これを防ぐため「14日鮮度上限」と「価格改定日（`priceEffectiveUntil`）切れチェック」を入れたところ、今度は**「料金と無関係なPRでも日付が進んだだけでCIが落ちる」**という非決定性の問題（Issue #52）が浮上しました。
- **機械化対策**: 構造検証と時刻依存チェック（`--time-sensitive`）を分離し、予定価格改定の自動切替（`scheduledPricing`）を実装。通常PRは決定的チェックのみ、日次監視ワークフロー（`daily-freshness-check.yml`）と料金ファイル変更PRのみ時刻チェックで失敗させる二段構えにしました。

### L-08: PIIマスカーで「株式会社〇〇の佐藤太郎様」が `[ORG_1]` に飲まれるバグ
- **何が起きたか**: 日本語法人名と氏名の間に助詞「の」が入る自然な文章で、法人名正規表現がひらがなを貪欲一致してしまい `[PERSON_1]` が消える不具合を人間が即発見（Issue #44）。
- **機械化対策**: 助詞境界制御とストップワードを整理し、サンプル文の往復復元で `[ORG_1]の[PERSON_1]` 生成と未解決トークン残存 0 件を Vitest と Playwright E2E の両方で強制しました。

### L-12: 公開リポジトリにおける外部Issueからのプロンプトインジェクション対策
- **何が起きたか**: この実験リポジトリは透明性のために公開していますが、誰でも起票できる Issue テンプレートに `owner:ai` / `status:ready` が付いていたら、**第三者が悪意ある指示文を Issue に書くだけで自律AIに任意作業を誘導できてしまう**リスクが見つかりました（Issue #51）。
- **機械化対策**: `ops_github.mjs` に `author_association`（`OWNER` / `COLLABORATOR` / `MEMBER`）と公式 `github-actions[bot]`（`type: 'Bot'`）のみを信頼する fail-closed な信頼境界を導入。外部IssueやフォークPRは `external_issues` / `external_pull_requests` へ隔離してデフォルトで本文・タイトルを省略する仕組みへ改修しました。

### L-14: 「ゼロ送信」表現と本番広告・解析タグの矛盾を潰す
- **何が起きたか**: サイトに「外部通信ゼロ」と書いておきながら本番で GA4 や AdSense を有効にすれば、Google 宛ての通信自体は必ず発生します（Issue #53）。
- **機械化対策**: 表現を「入力データ送信ゼロ」へ統一して未限定表現を `audit-seo-adsense.mjs` で拒否したうえで、**ダミーの AdSense/GA4 ID を有効化したビルドで全ツールへカナリア機密値を入力し、全通信と `window.dataLayer` に1文字も漏れないことを証明する `test:e2e:ads`** をCIへ組み込みました。

## 4. ここまでの振り返り：AIが得意なこと・まだ人間が不可欠なこと

ここまでの実戦で、AIと人間の境界線がはっきり見えてきました。

- **AIが強い領域**: 規約・競合調査からの設計、純粋TSロジックの高速実装、失敗を次の自動チェック（AST監査やPlaywright座標計測・E2E）へ落とし込む再発防止の仕組み化。
- **人間が効いている領域**: 「ファーストビューで入力欄が遠くて使いづらい」「見出しの『ブラウザ』が変な位置で改行されている」「この実務文だと人名がマスクされない」といった、**初見ユーザーとしての違和感の発見**、およびドメイン購入・AdSense等の実世界アカウント作業。

現在は公開ツールの拡充を進めながら、**検索流入とAdSense収益の立ち上がりを1日でも早く積み上げるため、先行公開と記事導線の並行稼働**へ舵を切っています。
