# 🎮 ゲームの手触り（Game Feel）・UI情報圧縮・演出設計バイブル
**〜桜井政博氏のゲーム制作原則と世界の名作ローグライトから学ぶ「説明を読ませず、触って気持ちいいゲーム」の作り方〜**

このドキュメントは、[Issue #19（ダイス・フォージ・ダンジョンの改善要望）](https://github.com/Nakako0281/GameCreateTeam/issues/19) で最高責任者（人間）から受けた以下の本質的指摘に基づき、**先人のゲームクリエイターの知恵と世界の名作の演出手法を体系化し、GCTが今後二度と「文字だらけで動かないスプレッドシートのようなゲーム」を作らないための恒久設計基準**として策定したものです。

## 1. 先人の知恵：『桜井政博のゲーム作るには』から借りる7大原則

『星のカービィ』『大乱闘スマッシュブラザーズ』シリーズの生みの親である桜井政博氏が解説する設計思想から、Webゲーム・ターン制ゲームに直結する7つの鉄則を定義します。

### 原則①：【説明を読ませない】「人は長文をまともに読まない」を大前提にする
- **知見**: ゲームを開いた瞬間に長い説明文やルール解説が並ぶのは悪手。プレイヤーは「勉強」をしに来たのではなく「遊び」に来ている。
- **GCTへの適用（Text Budget & Progressive Disclosure）**:
  - **初期画面（タイトル・クラス選択）に文章（2文以上の説明）を載せることを禁止する**。表示してよいのは「アイコン」「名前」「10文字以内の直感タグ（例：`🗡️ 手数×猛毒`）」のみ。
  - バトル画面の常時表示テキストは **「アイコン＋数字（例：`🗡️ 8`、`🛡️ 12`、`×1.75`）」** に徹底圧縮する。
  - 詳細な効果説明は常時表示せず、**プレイヤーが気になった時にダイスやレリックをタップした時だけ1行ポップアップで表示する（段階的開示：Progressive Disclosure）**。

### 原則②：【ノーリアクションの排除】すべての入力に即座の視覚・聴覚反応を返す
- **知見**: ボタンを押したとき、選択したとき、たとえ無効な操作であっても「画面と音が即座に反応する」ことで初めてプレイヤーは「自分が世界に触れている」と感じる。
- **GCTへの適用**:
  - ダイス選択時：ダイスが `scale(1.12)` で浮き上がり、発光リングが脈動する。
  - スロット配置時：スロットがバウンス（`scale(1.15) -> 1.0`）して輝き、予測ダメージ数値がポップアップ拡大する。
  - リロール時：ダイスが実際に回転・シェイクしながら出目が切り替わる。

### 原則③：【予備動作 ➔ ヒット ➔ フォロースルー】0ミリ秒の即時状態書き換えを禁止する
- **知見**: 攻撃ボタンを押した瞬間に0ミリ秒で敵のHPが `38 ➔ 9` に書き換わるだけでは、脳は「何が起きたか」を認識できず、ただの事務作業になる。すべてのアクションには **「予備動作（タメ）➔ 実行（移動・軌跡）➔ 着弾（ヒット）➔ 余韻（フォロースルー）」** の時間軸が必要。
- **GCTへの適用**:
  - ターン実行時は必ず以下の**アニメーション・コレオグラフィ（時間軸シーケンス）**を再生する：
    1. **スロット順次発火（1ステップ 140ms）**: 配置したダイススロットが左から順に光り、剣・盾・魔力のエフェクトがチャージされる。
    2. **プレイヤー攻撃モーション（予備動作 ➔ 踏み込み ➔ 斬撃軌跡）**: プレイヤーアバターが前方に鋭く踏み込み（Lunge）、敵に向かって斬撃スラッシュ／魔導レーザーが走る。
    3. **敵の被弾リアクション ➔ 敵の反撃モーション（予備動作 ➔ 突進 ➔ 被弾/防御）**: 敵が生き残った場合、敵が大きく振りかぶってからプレイヤー側へ突進して攻撃する。

### 原則④：【ヒットストップと揺れの非対称性】「重み」と「手応え」を生む瞬間停止
- **知見**: 攻撃が当たった瞬間に数フレーム（約 `60〜90ms`）動きをピタッと止める「ヒットストップ」を入れることで、攻撃の重みが劇的に増す。このとき、**ダメージを受けた側を大きく揺らし、攻撃した側は小さく止める（揺れの非対称性）**のが鉄則。
- **GCTへの適用**:
  - 敵への着弾時：`70ms` のヒットストップ＋敵アバターの白/赤フラッシュ＋敵側の激しいノックバック振動＋大ダメージ時の画面シェイクを発動する。
  - 敵撃破時：長めのヒットストップ（`140ms`）＋敵が砕け散るパーティクルバーストを入れてから報酬画面へ遷移する（0秒でいきなり報酬モーダルを被せない）。

### 原則⑤：【エフェクトは情報伝達の言語】文字ではなく「色・形・画面フラッシュ」で伝える
- **知見**: エフェクトは単なる飾りではなく、「今ダメージを与えた」「今ガードした」「今痛い攻撃を食らった」を一瞬で脳に伝える視覚言語である。
- **GCTへの適用**:
  - **敵にダメージを与えた時**: 敵の上に大きなダメージ数値（`-29!`）が跳ね上がり、斬撃エフェクトが走る。
  - **自分がシールドを獲得した時**: プレイヤーの周囲に青いバリアリングが展開される。
  - **敵の攻撃をシールドで防いだ時**: 青い火花と `BLOCK!` フロート表示が出て、プレイヤーのHPは無傷であることが視覚的にわかる。
  - **自分がHPダメージを受けた時**: **画面全体が一瞬赤くフラッシュ（Red Vignette Flash）** し、画面全体が横に揺れ、プレイヤー上に赤い `-8` が跳ねる。

### 原則⑥：【視覚的ヒエラルキー】重要な数字は特大に、補足情報は隠す
- **知見**: すべて同じサイズの文字で並べると、どこを見ればいいか分からなくなる。
- **GCTへの適用**:
  - ダイスの出目（`1`〜`6`）、敵の次ターン攻撃値（`🗡️ 8`）、与ダメージ予測、跳ね上がるダメージポップアップは大きく太いフォント（`18px〜28px`）で表示し、説明文は画面から排除する。

### 原則⑦：【小気味よいテンポ】リッチな演出と高速テンポを両立させる
- **知見**: 演出を入れることでゲームがモッサリしては本末転倒。キビキビとしたイージング（急加速・急減速）で、1ターン全体の演出を `0.8〜1.1秒` 以内に小気味よく完結させる。

## 2. 世界の名作ターン制/ダイスゲームから借りる3大演出技法

ターン制・UI主体のゲームでありながら「アクションゲーム以上に気持ちいい手触り」を実現している世界の名作3タイトルから、具体的な仕組みを取り入れます。

| 参考タイトル | 借りる仕組み | 本作（ダイス・フォージ・ダンジョン）への落とし込み |
| :--- | :--- | :--- |
| **『Balatro』** | **リレー式カウントアップ＆倍率ポップ演出**<br>結果を一気に出さず、カード（スロット）が左から順番に「ポン！ポン！」と鳴りながら数値を加算し、最後に倍率（`×Mult`）が跳ねて総ダメージが確定する。 | ターン実行時、配置済みのスロットが左から順番にハイライト発火し、共鳴役バッジ（`STRAIGHT ×1.75`）が弾けてから敵へ一撃を叩き込む。 |
| **『Slay the Spire』** | **左右対峙構図（Duel Arena）と頭上インテント**<br>画面左にプレイヤー、画面右に敵が向かい合って立ち、敵の頭上にシンプルなアイコンと数字（`🗡️ 8`）だけが出る。攻撃時はキャラ自体が相手に体当たりする。 | バトルアリーナを「左：プレイヤー（クラスアイコン＋HP＋盾オーラ）」「右：敵モンスター（アイコン＋HP＋頭上インテント `🗡️8`）」の対峙構図に刷新し、双方が動いて殴り合う。 |
| **『Dicey Dungeons』** | **サイコロの物理的なおもちゃ感（Toy Feel）**<br>サイコロがただのテキストボタンではなく、立体的なダイスとしてコロコロ転がり、スロットにカチッとはまる。 | ダイストレイとスロットから長ったらしい文字（`素の刻印 [1]` 等）を廃止し、**「大きな出目数字＋属性アイコン」の立体ダイスブロック** に刷新する。 |

## 3. 現時点の『ダイス・フォージ・ダンジョン（初版）』との徹底比較（Gap Analysis）

世の中の名作・桜井氏の原則と、改修前の『ダイス・フォージ・ダンジョン（初版）』を画面ごとに比較し、問題点を洗い出しました。

| 比較項目 | ❌ 初版の『ダイス・フォージ・ダンジョン』（問題点） | ✅ 世の中の名作・桜井氏の原則に基づく改善設計 |
| :--- | :--- | :--- |
| **① タイトル・クラス選択画面の文字量** | ・サブタイトル、長いリード文、3クラスそれぞれに3行ずつの長文説明（計250文字超）が並び、開いた瞬間に「これ全部読むのか…」と萎える。 | ・リード長文を全撤廃。<br>・クラス選択は **「アイコン＋クラス名＋10文字タグ（例：`🗡️ 小目1・2×猛毒連撃`）」** の1行カードに圧縮。<br>・画面全体の文字数を **70%以上削減** し、開いて1秒で「出撃」できるデザインにする。 |
| **② バトル画面の構図と情報密度** | ・敵アイコンが上部のカード内と中央に2つ重複して存在し、プレイヤー自身の姿が画面に存在しない（誰が戦っているか分からない）。<br>・ダイスやスロットに `素の刻印 [1]` 等の冗長な文字が書かれている。<br>・常時表示の1行解説バー（`💡 Floor 1 開始！まずは...`）が場所を取っている。 | ・中央アリーナを **「左：プレイヤー」vs「右：敵モンスター」の対峙構図（Duel Arena）** に統一。<br>・敵の行動予告は頭上に **`🗡️ 8`** のようにアイコン＋数字で直感表示。<br>・ダイスは **「出目数字＋刻印アイコン」** のみの視覚的サイコロにし、長文テキストバーは廃止（タップ時のみ短いポップアップ表示）。 |
| **③ ターン実行時のアニメーション・操作感** | ・「ターン実行」を押した瞬間、**0ミリ秒で計算結果のstateに飛び、攻撃モーションも被弾エフェクトも一切ない**。<br>・敵を倒した瞬間も、攻撃が当たったことすら分からないまま0ミリ秒で「突破報酬モーダル」が画面を覆う。 | ・ターン実行を **段階的アニメーション・シーケンス** に変更：<br>  1. スロット順次発火（ポン・ポン・ポン）<br>  2. プレイヤー踏み込み＋斬撃/魔導エフェクト＋敵ヒットストップ＆赤白点滅＆ノックバック＆ダメージ数値ポップ（`-29!`）<br>  3. 敵撃破時は撃破バースト演出を見届けてから報酬へ／生存時は敵が踏み込んで反撃＋プレイヤー被弾時の**画面全体赤フラッシュ＆シェイク**（盾防御時は青バリア火花 `BLOCK!`）。 |
| **④ 鍛造報酬・ショップ画面の文字量** | ・「① 獲得する魔導刻印を選択（3択）」「② 彫り直すダイスと面を選択…」など、説明見出しとカード内長文がびっしり詰まっている。 | ・説明見出しを極限まで短縮（`⚒️ 刻印を選んでダイス面に鍛造`）。<br>・刻印カードも **「出目バッジ＋名前＋簡潔な効果（`威力+4 / 2連撃 / 毒+3`）」** のタグ形式に整理し、彫り込んだ瞬間にハンマー打撃エフェクトとダイス面の輝き演出を入れる。 |

## 4. Issue #21 で確立した3つの絶対鉄則（`R-09`〜`R-11`）

### 鉄則⑧：Unicode絵文字の100%完全禁止（`R-09`）
- **問題の本質**: OS標準の絵文字（🎲, ⚔️, 🛡️, 👹, ❤️ 等）を並べた瞬間、どんなにシステムを作っても「安っぽいAI製のWebフォーム」「手抜きプロトタイプ」にしか見えない。
- **恒久対策**:
  1. ゲーム画面・プラットフォーム画面・データ定義から **Unicode絵文字（`\p{Extended_Pictographic}`）を1文字残らず完全追放** し、単体テストとE2Eテストで絵文字混入0件を自動監視する。
  2. サイコロは「文字で数字とラベルを書いた四角」ではなく、**本物のサイコロの目（1〜6のピップドット）＋属性紋章を描画したカスタムSVG/Canvasダイス**として描く。
  3. プレイヤーとモンスターは、関節や武器・発光パーツを持ち、呼吸・踏み込み・斬撃・被弾ノックバック・撃破粉砕アニメーションを行う **Canvas 2Dカスタムスプライト（またはSVGベクターアート）** として描画する。

### 鉄則⑨：文字と表で遊ばせない「説明ゼロ・即時ダイレクト操作」（`R-10`）
- **問題の本質**:
  - 「ダイスを5つの空箱に並べてから、別の『実行』ボタンを押すまで何も起きない（あるいは『自動』ボタンでAIが勝手に進める）」構造は、ゲームではなくスプレッドシート（表計算）の入力作業である。
  - また、タイトル画面やバトル画面にルール説明や長文ラベルが残っていると、プレイヤーは読む気を失って離脱する。
- **恒久対策**:
  1. **ダイレクト・ウェポン・アクション方式**: ダイスを選んだ状態で「武器・スキルカード（剣・双剣・盾・魔導砲など）」をタップした**その瞬間**に、キャンバス上のヒーローが敵へ踏み込んで斬りつけ（または盾を展開し）、ヒットストップ・斬撃エフェクト・ダメージポップアップ・HPバー減少が**リアルタイムに即座に発動する**構造にする。
  2. **プレイヤーから手触りを奪う「自動配置（Auto）ボタン」の廃止**: プレイヤー自身が1個ずつダイスを武器に叩き込む快感をコア体験とする。
  3. **説明文ゼロでも目で見て分かる数値プレビュー**: 選択中のダイスに応じて、各武器カード上に「今これを押したら何ダメージ出るか（例：`14 DMG`、`+10 DEF`）」をリアルタイム表示し、ルール説明を1文字も読まなくても直感的に最適解を探せるようにする。

### 鉄則⑩：AIチームの自律的セルフリジェクト（自己ダメ出し＆再設計）ゲート（`R-11`）
- **問題の本質**: 人間（最高責任者）から「つまらない」「文字が多い」と言われるまでAIチームが問題に気づけない（あるいは形式的なテスト通過だけで満足してしまう）ことが最大のリスクである。
- **恒久対策**:
  - Stage 4（PR提出前）において、AIチーム（`00_director`, `04_critic`, `07_blind_playtester`）は必ず撮影されたスクリーンショットと動画を実際に開き、以下の**自律棄却（Self-Rejection）チェック**を行う：
    1. **「Web管理画面・HTMLフォームに見えないか？」**: 絵文字やテキストボタンの羅列に見えたら即座に `❌ 自己棄却` とし、Canvas/SVG描画とダイレクト操作へ作り直す。
    2. **「Flash時代の名作や『スイカゲーム』『Dicey Dungeons』『80億分の1』と並べて、初見の人間が説明なしで夢中になれるか？」**: 1秒で触り方が分かり、触った瞬間に気持ちいい反応が返ってこなければ提出してはならない。

### 鉄則⑪：奇をてらった複雑ルールを捨て、王道の「レベルアップ×ステージ進行×シンプルなダイス運」にする（`R-12`）
- **問題の本質**:
  - 手触りが良くても、「毎階層サイコロの特定の面（24面）を彫り直す」「仮枠に置いてから別ボタンを押すまで敵が倒れない」「途中から突然別画面の祭壇・ショップに飛ぶ」といった奇をてらった複雑ルールが挟まると、プレイヤーはルールを把握できず迷子になる。
- **恒久対策**:
  1. **王道の成長サイクル**: 「ステージの敵を倒す ➔ **LEVEL UP!**（HP・攻撃力自動成長＋3択スキル強化）➔ **次のステージへ**」という説明不要の王道リズムにする。
  2. **ダイスは「ランダムな行動パワー源」に徹する**: 振った出目で役倍率（ペア・ストレート等）が即座に決まり、選んだコマンドカード（斬撃・毒連撃・盾防御・魔導）にそのまま叩き込むことで直感的な戦闘手触りとランダム性の楽しさを両立させる。

### 鉄則⑫：0ベースでのダイス意味設計・即時HP反映・連打クリアの排除（`R-13`, `R-14`）
- **問題の本質**:
  - 「自動」「一斉攻撃」ボタンが残っているとプレイヤーは「どのボタンを押せばいいのか」迷う上、思考停止で一斉攻撃を連打するだけで盾も張れてStage 12まで勝ててしまい達成感がない。
  - また、キャラのステータス差・技と出目の関係・報酬カードの効果が省略されて見えないと、「何を選べば強くなるか」判断できない。
- **恒久対策**:
  1. **1ダイス＝1即時アクションへの一本化**: 「自動」「一斉攻撃」を撤廃し、選択中ダイスで技ボタンをタップした瞬間にその場でダイスを消費し、即座に敵HPの減少やシールド獲得を確定・演出する。
  2. **出目×技の明確な意味付け**: 「強斬撃（4〜6で会心）」「毒連撃（1〜3で2連+毒）」「鉄壁盾（偶数で装甲強化）」「魔導砲（MP蓄積＆MP3で必殺）」のように、出目ごとの役割と現在選択ダイスでの確定効果をボタンに明示する。
  3. **思考停止連打の確実な敗北**: 敵の行動予告を見ずに攻撃技だけ連打すると序盤（Stage 2〜4）で確実に敗北し、防御や出目の使い分けで初めて勝てる手応えにする。

### 鉄則⑬：3ゾーン高さ完全ロック ＆ 能力の上部常時表示（`R-15`）
- **問題の本質**:
  - タイトル画面・キャラ選択画面・戦闘画面・報酬画面の遷移ごとに下部ボタンや戦場キャンバスの高さがガタガタ動くと、操作感と視線誘導が著しく損なわれる。また、自分の能力を別モーダルに隠すと把握しづらい。
- **恒久対策**:
  1. **固定3ゾーン構造**: 上部ステータスバー（`76px`）・中央戦場キャンバス（`flex-1`）・下部コントロールデッキ（`296px`）の枠組みを全画面で維持し、遷移時のレイアウト変動（ガタつき）を 0px に抑える。
  2. **常時表示の能力・特性バー**: クラス特性・獲得遺物・進化スキルを上部76pxバー内に常時表示する。

### 鉄則⑭：専用タイトル画面からの導入（`R-13`）
- **恒久対策**:
  - 起動直後にキャラ選択を迫るのではなく、ゲームの雰囲気と3ステップ（ダイスを振る ➔ 技に叩き込む ➔ 成長して制覇）を一目で伝えるタイトル画面を最初に提示する。

## 5. 同じ指摘を二度と受けないための組織・検証ゲート改革

この知見を単なる掛け声で終わらせず、**今後のすべてのゲーム開発で自動的に強制される仕組み**として以下の5つを組織体制に組み込みます。

1. **メンバー役割の強化（`00_director.md`, `02_game_designer.md`, `03_art_sound.md`, `04_critic.md`, `07_blind_playtester.md`）**:
   - **UI/UX＆アート（03）**: Unicode絵文字完全禁止（`R-09`）、カスタムSVG/Canvas描画、画面内テキスト極小化（`R-10`）の実装責任者とする。
   - **辛口レビュアー（04）＆ 初見プレイテスター（07）**: 実機スクショ・動画を見て「つまらないWebフォームになっていないか」を審査し、基準未満なら人間へ出す前に無条件で差し戻す（`R-11`）。
2. **単体テスト＆E2Eテストでの「絵文字ゼロ（0 Emoji）」自動強制ゲート**:
   - `registry.test.ts` および Playwright E2E テストにて、`/\p{Extended_Pictographic}/u` による全テキスト・データ走査を行い、絵文字が1文字でも混入していればCI/テストを即座にFAILさせる。
3. **E2Eテストでの「超低文字量ゲート」＆「即時ダイレクトアクション検証ゲート」**:
   - タイトル画面およびバトル画面の日本語文字数が極小（説明文ゼロ）であること、およびダイスを武器に使った瞬間に即座に戦闘アクションとダメージが発生することを自動検証する。
4. **最高責任者レビュー台帳（`docs/REVIEW_GUIDELINES_AND_LOG.md`）への恒久記録（`R-06`〜`R-11`）**:
   - 企画提出時・PR提出時に毎回必ず照合する。
