# 失敗・教訓・機械化再発防止台帳 (`docs/POSTMORTEM_AND_LESSONS.md`)

> **絶対原則**: 本台帳に記録した教訓に対し「次回から気をつけます」と書いて終わることを禁止する。客観検証可能なシステム・状態欠陥は **必ず「ハーネス（Hooks/CLI/CI）または自動テスト」へ落として物理的に再発を封じ**、判断・対話原則は憲法/ADRの最小記述へ反映する（精神論や態度を縛る文言正規表現チェックは追加しない）。

## 再発防止レイヤー分類（Resolution Tier）＆ ルール退役基準（Issue #56）

常時読み込みルール（`AGENTS.md` / `.agents/rules/AGENTS.md`）の肥大化を防ぐため、すべての教訓は以下の3段階のいずれかで解決し、`scripts/audit-org-memory.mjs` で分類タグと実装証跡パスの記載を機械強制する：
- **`[Tier A: Code/Test]`**: アプリケーション実装修正 ＋ 単体/E2Eテスト追加で完結（**ルール文書への追記禁止**）。
- **`[Tier B: Harness/CLI]`**: `scripts/ops_github.mjs`・`scripts/audit-*.mjs`・Hooks・CIワークフローによる物理拘束（**常時読み込みルールへの追記禁止**）。
- **`[Tier C: Principle]`**: 機械判定できない権限境界（RACI）・対話原則のみ憲法/ADRへ反映。常時読み込みルールへ追記する際は、既存の重複・ハーネス代替済み記述を統合またはADRへ退避する **`1-in-1-out` 原則** を適用する。
- **ルール退役（Sunset）3基準（週次 `audit-and-evolve` で点検）**: ①CLI/監査エラーメッセージだけで行動修正できる細則の削除、②初期移行フェーズ完了記述の削除、③2週間連続 `null`/発動ゼロの形骸化仕組みに対する「CLI強制へ昇格」または「廃止」の二択決裁。
