# 📜 最高責任者レビュー指針 ＆ 指摘履歴台帳 (`REVIEW_GUIDELINES_AND_LOG.md`)

このドキュメントは、最高責任者（人間）からいただいたレビュー指摘・制作方針を恒久的に記録し、**①同じ指摘の再発を100%防ぐこと**、および **②過去の方針と新しい指示の間に矛盾や変更が生じた際にAIが気づいて確認できるようにすること** を目的とした最上位チェック台帳です。

> [!IMPORTANT]
> **【AIチームの必須運用ルール】**
> 1. **企画書・PRの提出前チェック**: 人間へ企画書（MD）やPRを提出する前に、ディレクター（`00`）と辛口レビュアー（`04`）は必ず本ドキュメントおよび [`docs/GAME_FEEL_AND_UX_PRINCIPLES.md`](./GAME_FEEL_AND_UX_PRINCIPLES.md) の全項目を照合し、違反や抜け漏れがないか確認すること。
> 2. **レビュー受領時の即時記録**: 人間からIssueコメントまたはチャットで指摘を受けた際は、作業を進める前に必ず本ドキュメントに追記すること。
> 3. **過去指針との矛盾検知・確認プロトコル**: 新しい指示が本ドキュメントの「恒久指針」や「過去の指摘」と矛盾・変更になる場合は、勝手に判断せず **「過去のレビュー（#XX）では〇〇という方針でしたが、今回は△△へ方針変更（または今作の特例）として進めてよろしいでしょうか？」** と人間へ確認すること。

## 1. 恒久ゲーム制作・開発指針（Active Guidelines）

### R-01: レビュー指摘の蓄積・事前照合・矛盾チェックの徹底
- **内容**: ゲーム制作に関するレビュー指摘はすべて本台帳に記録し、次回以降のレビュー提出時に毎回必ず参照して同じ指摘が起きないようにする。また、過去の指摘と矛盾する指示があった場合は人間側のミスの可能性も含めて指摘・確認する。
- **策定元**: [Issue #12 コメント](https://github.com/Nakako0281/GameCreateTeam/issues/12#issuecomment-6889464607) (2026-11-15)

### R-02: アセット（効果音・音楽・画像）におけるフリー素材＆AI生成の積極活用
- **内容**:
  - 無理に「Web Audio APIによるプログラム合成音」や「Canvas/SVGの図形描画のみ」に縛られる必要はない。
  - **効果音（SE）・BGM**: 人間側で無料のフリー素材（効果音ラボ、魔王魂、DOVA-SYNDROME、Kenney、itch.io、Pixabay Audio等）をダウンロードして用意することが可能。必要な素材リストをAIから提示すれば人間側で調達する。
  - **静止画・イラスト・UI素材**: Gemini（`image-generator` サブエージェント等）によるAI画像生成や、無料フリー素材のダウンロードを組み合わせてリッチに制作してよい。
  - **補足（Web Audioの役割）**: フリー素材の音声ファイルを再生する際、コンボ連鎖に応じてピッチ（再生速度）を段階的に上げる演出や音量制御などの補助としてブラウザのAudio機能を使うのは有効だが、「外部音声ファイル禁止・合成音のみ」という旧制約は完全撤廃する。
- **策定元**: [Issue #12 コメント](https://github.com/Nakako0281/GameCreateTeam/issues/12#issuecomment-6889464607) (2026-11-15)

### R-03: 外部ツール・ライブラリの活用と人間への調達依頼フロー
- **内容**:
  - 制作に必要なツール、NPMライブラリ、フリー素材などがあれば、遠慮なく人間へ「これを用意・導入したい」と伝えること（企画書内に「必要な素材・ツール・ライブラリ一覧」を明記する）。
- **策定元**: [Issue #12 コメント](https://github.com/Nakako0281/GameCreateTeam/issues/12#issuecomment-6889464607) (2026-11-15)

### R-04: 「完全無料（Free to Use）」の原則
- **内容**:
  - 開発に使用する素材（音・画像・フォント等）、ツール、ライブラリは、**すべて無料で使えるもの（無料フリー素材・OSSライブラリ・既存の無料枠ツール）** に限定すること。有料アセットや課金が必要な外部API/サービスを前提とした設計は行わない。
- **策定元**: [Issue #12 コメント](https://github.com/Nakako0281/GameCreateTeam/issues/12#issuecomment-6889464607) (2026-11-15)

### R-05: プラットフォーム形式（案A）の継続と旧体制6作品の完全削除
- **内容**:
  - プラットフォーム形式（`AI Game Lab`）は継続しつつ、旧体制（瞬間バズ狙い）で制作した過去6作品（`slice-5050`, `ihou-kenchiku-burger`, `midnight-poem-defense`, `teiji-taisha-parry`, `shazai-angle-challenge`, `candy-pop-reversi`）のロジック・ゲームコード・テストはすべて削除し、新体制の『ダイス・フォージ・ダンジョン』以降のゲームのみを収録する。
- **策定元**: 最高責任者指示 (2026-11-15)

### R-06: 文字・説明の徹底削減（「人は長文を読まない」原則・Progressive Disclosure）
- **内容**:
  - ゲームを開いた瞬間に「この文章をすべて読まなければならないのか」と思わせる説明文・長文UIは絶対禁止。文字は本当の本当に必要な最小限（アイコン＋数値＋短い単語タグ）に絞ること。
  - **タイトル・初期選択画面**: 長いリード文やクラスごとの2〜3行の説明文を排除し、「アイコン＋名前＋10文字以内の特徴タグ」のみで1秒で開始できるようにする（Playwright E2Eでタイトル画面の可視文字数を上限チェックする）。
  - **プレイ画面**: 常時表示の解説テキストバーや冗長なラベル（`素の刻印 [1]` 等）を撤廃し、視覚的なサイコロ・アイコン・数字だけで直感的に遊べるようにする。詳細効果はプレイヤーが気になった時にタップした際だけツールチップで表示する（段階的開示：Progressive Disclosure）。
- **策定元**: [Issue #19](https://github.com/Nakako0281/GameCreateTeam/issues/19) (2026-11-15) / 詳細基準: [`docs/GAME_FEEL_AND_UX_PRINCIPLES.md`](./GAME_FEEL_AND_UX_PRINCIPLES.md)

### R-07: 「0ミリ秒状態書き換え」の禁止 ＆ アクション手触り（モーション・ヒットストップ・画面フラッシュ）の必須化
- **内容**:
  - ボタンを押した瞬間に0ミリ秒で数値（HP等）だけがパッと書き換わる「表計算（スプレッドシート）のような画面遷移」は絶対禁止。
  - **対峙構図とモーション**: 誰が誰に攻撃しているか一目でわかるよう、プレイヤーと敵を画面内で対峙させ、攻撃時は踏み込みモーション（Lunge）・斬撃/弾道エフェクトを必ず描画する。
  - **ヒットストップと被弾リアクション**: 攻撃着弾時には瞬間停止（ヒットストップ `60〜90ms`）、ダメージ数値のポップアップ跳躍、敵の白/赤点滅とノックバック振動を入れる。また、プレイヤーがダメージを受けた際は**画面全体の赤フラッシュ＋画面シェイク**（シールド防御時は青バリア発光＋`BLOCK!`）を入れ、「操作している実感・手応え」を必ず演出する。
- **策定元**: [Issue #19](https://github.com/Nakako0281/GameCreateTeam/issues/19) (2026-11-15) / 詳細基準: [`docs/GAME_FEEL_AND_UX_PRINCIPLES.md`](./GAME_FEEL_AND_UX_PRINCIPLES.md)

### R-08: 独りよがりな設計・改善の禁止 ＆ 先人の知恵（桜井政博氏ら）・名作事例の調査とギャップ比較の徹底
- **内容**:
  - 企画や改善を行う際、AIの思いつきだけで作り始めることを禁止する。
  - 必ず『桜井政博のゲーム作るには』をはじめとする先人のゲームクリエイターの知見や、同ジャンルの世界的名作（『Balatro』『Slay the Spire』『Dicey Dungeons』等）が「どのように直感理解と没入感を演出しているか」を調査し、現状のゲームと比較（Gap Analysis）した上でドキュメントに残し、設計と自動テストゲートに落とし込むこと。
- **策定元**: [Issue #19](https://github.com/Nakako0281/GameCreateTeam/issues/19) (2026-11-15) / 詳細基準: [`docs/GAME_FEEL_AND_UX_PRINCIPLES.md`](./GAME_FEEL_AND_UX_PRINCIPLES.md)

## 2. 企画書・PR提出時のセルフチェックリスト（毎回確認）

- [ ] **リトライ性**: 1回で飽きる出落ちではなく、複数ビルド・戦略で何度も繰り返し遊べるか？
- [ ] **プレイ時間**: ゲームのコアループが最も輝くプレイ時間を設定し、5分以上の場合は `localStorage` 中断オートセーブを設計したか？
- [ ] **文字量の徹底削減（R-06）**: タイトル画面・プレイ画面に長文説明が並んでいないか？開いて1秒で遊び始められ、アイコンと数字だけで直感的に理解できるか？
- [ ] **手触り・アニメーション・コレオグラフィ（R-07）**: 0ミリ秒で数値だけ変わる事務画面になっていないか？攻撃モーション、ヒットストップ、被弾時の画面フラッシュ・シェイク、ダメージ数値ポップアップが実装されているか？
- [ ] **先人の知恵・名作との比較（R-08）**: [`docs/GAME_FEEL_AND_UX_PRINCIPLES.md`](./GAME_FEEL_AND_UX_PRINCIPLES.md) の7原則を満たし、世の中の名作と比べて見劣りしない演出密度になっているか？
- [ ] **アセット＆ライブラリ計画（R-02, R-03, R-04）**: すべて無料で利用できる素材・ライブラリになっており、必要なフリー素材はリスト化したか？
- [ ] **過去指摘との整合性（R-01）**: 過去のレビュー指摘と同じミスをしていないか？
